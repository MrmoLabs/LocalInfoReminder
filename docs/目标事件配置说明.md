# 目标事件配置说明

## 1. 当前结构

`target_event_detection` 现在只保留 `targets` 列表，所有用例的 OCR 关键字、结果关键字、屏蔽关键字、时间窗口和持续时间都由各自 target 独立维护。

```json
{
  "target_event_detection": {
    "targets": [
      {
        "id": "target_a",
        "display_name": "目标A",
        "match_names": ["Target A", "目标A"],
        "ocr_keywords": ["目标A"],
        "time_windows": [
          {"start": "27:10", "end": "24:30"},
          {"start": "17:20", "end": "14:30"}
        ],
        "result_window_seconds": 180,
        "result_keywords": ["完成", "结束"],
        "ignore_keywords": ["示例", "忽略"],
        "faction_match": "distinguish",
        "spawn_sound": "",
        "result_sound": "",
        "buff_duration": 120
      }
    ]
  }
}
```

## 2. 已经移除的公用根字段

以下旧字段已不再作为新配置的输出结构：

- `notification_windows`
- `kill_check_timeout_seconds`
- `spawn_keywords`
- `result_keywords`
- `ignore_keywords`
- `boss_buff_durations`

旧配置仍可被读取并迁移到对应 target，但保存后会按新结构写回。

## 3. 检测链路

目标事件现在使用两个独立 ROI：

- `target_event_notification`: 用于播报文本 OCR 识别
- `target_event_result`: 用于结果文本 OCR 识别

运行时会结合以下信号进行判定：

1. 先看当前 target 是否在 `time_windows` 内
2. 在相应 ROI 中执行 OCR
3. 检查 `ocr_keywords` 或 `result_keywords` 是否命中
4. 用 `ignore_keywords` 剔除明显无效的文本
5. 用 `vision_detection.color_profiles` 中的颜色采样和阈值进行类别辅助判断

## 4. ROI 编辑与调试

在“目标事件设置”顶部保留了原来的 `查看 / 调整目标OCR区域` 入口。该入口会直接打开 ROI 编辑器，并可在内部切换播报区和结果区。

在 ROI 编辑器中：

- `区域概览` 分页用于调整 ROI 位置和尺寸
- `联动调试` 分页可同时查看颜色取样、命中遮罩、OCR 结果和关键字匹配
- `Ctrl + T` 可手动测试 OCR，颜色参数发生变化后会防抖自动刷新 OCR

## 5. 调参建议

- 先用 ROI 编辑器确认播报区和结果区是否框对
- 再调整 `ocr_keywords`、`result_keywords` 和 `ignore_keywords`
- 如果 OCR 命中但类别判断不稳，再调整颜色采样、容差和命中比例
- 优先维持关键字精简，不要无限堆叠近似词
